Open-source tracing

Every request, followed to the slow span.

Tracewire is a CLI and a dashboard that stitches OpenTelemetry spans into one waterfall, then points at the span that cost you the most time.

Install the CLI See how it works
$ brew install tracewire
OpenTelemetry native MIT licensed Runs on your laptop

Install

Three commands from zero to a trace.

Install the binary, point your services at the collector it starts, then ask for the slow requests. The collector speaks OTLP, so the SDKs you already use keep working.

  • macOS, Linux and Docker
  • Traces stay on your machine
  • One YAML file, checked into the repo
terminal
# 1. install the binary
brew install tracewire

# 2. start the collector and the dashboard
tracewire up --service checkout-api

  collector   listening on :4317 (OTLP gRPC)
  dashboard   open localhost:7070
service: checkout-api
collector:
  endpoint: localhost:4317
sample:
  rate: 0.25
  always: [errors, slower_than_300ms]
retain: 7d
tracewire query 'service = "checkout-api" and duration > 300ms' --since 1h

How it works

From loose spans to the line that slowed you down.

One trace, four views. Scroll and the waterfall on the right changes with each step.

  1. Instrument

    Keep the OpenTelemetry SDK you have, or let the CLI add auto-instrumentation for Node, Go and Python. Spans start arriving the moment a request runs.

    • OTLP over gRPC and HTTP
    • No code change for the auto path

  2. Stitch

    Spans from every service join on their trace and parent ids. Six fragments from four processes become one request you can read top to bottom.

    • W3C trace context
    • Clock skew corrected per host

  3. Find

    Tracewire walks the critical path and dims everything that ran in parallel. What is left is the chain of spans the user actually waited on.

    • Critical path, not just the longest bar
    • Attributes inline

  4. Compare

    Lay this trace over the same route before your last deploy. The span that grew is marked with the commit that shipped it.

    • Diff by route and deploy
    • Links back to the commit

Your slowest span has a name. Go and read it.
